# MACS Case Study Presentation Rule

Homepage case studies should follow a compressed Collins-inspired structure:

- client / context
- one transformation sentence
- what they came in with
- what MACS consolidated or changed
- what remains owned / portable
- one clear next action

Do not use fabricated performance metrics, testimonial language or decorative proof. Each case page should explain a capability of MACS through a real transformation rather than a feature list.
