# Growth Experiment Lab

This folder is the durable evidence layer for commercial experiments run through Reset, Momentum, Scale, and Launch.

## Rule

Do not treat an idea, framework, benchmark, or model recommendation as a win until observed behavior supports it.

Each material test gets its own Markdown file created from `TEMPLATE.md`.

Suggested filename:

`YYYY-MM-DD_<client>_<bucket>_<short-test-name>.md`

Example:

`2026-09-05_macs_momentum_homepage-cta.md`

## One test, one primary question

Prefer a single commercial hypothesis per experiment. A tightly coupled bundle is acceptable only when the pieces cannot reasonably be tested independently.

## Lowest-hanging-fruit order

Before opening a test, ask:

1. What is the problem closest to money today?
2. Is there already evidence that settles it?
3. What is the smallest reversible test that can change our confidence?
4. Can we use an existing audience, asset, process, or channel first?
5. What would we stop doing if this test wins?

## Evidence hierarchy

Rank evidence roughly in this order:

1. cash / gross profit
2. closed sales
3. qualified pipeline
4. engaged leads / booked calls
5. conversion behavior
6. retention / repeat use
7. owner time saved
8. attention metrics

Use lower-level signals for diagnosis, not to declare commercial victory.

## Decisions

Every completed experiment ends in one state:

- KILL
- KEEP
- IMPROVE
- SCALE

Do not leave completed tests as `interesting` or `inconclusive` without stating what evidence is missing and the next test that would resolve it.

## Claims

Experiment results are internal evidence until separately approved for public use. Customer names, testimonials, screenshots, financial results, and relationship claims require the applicable owner/client consent gate before publication.
