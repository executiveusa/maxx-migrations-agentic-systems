# 01 — TRUTH

## Purpose
Establish current reality before prescribing a redesign.

## Inputs
- repository and current branch
- live deployment(s)
- current routes and user journeys
- current copy/content
- analytics/search/runtime evidence if available
- existing forms/APIs/integrations
- brand/founder/client assets
- case studies and approved claims
- relevant competitors/reference sites

## Process
Inspect the actual product, not a description of it. Separate FACT, INFERENCE, HYPOTHESIS, DECISION, and EVIDENCE. Inventory working brownfield capabilities. Identify contradictions between repo, deployment, positioning, and proof.

## Outputs
- `TRUTH.md`
- `CURRENT_SITE_MAP.md`
- `PROOF_INVENTORY.md`
- `KEEP_REMOVE_MOVE.md`
- known blockers / unknowns

## Evidence
URLs, commit SHAs, screenshots, file paths, build/runtime evidence, approved source material.

## Human/authority check
Only ask the owner for facts that cannot be discovered or resolved from authoritative sources.

## Exit condition
An agent can explain what exists, what is working, what is broken, what is merely claimed, and what must be preserved without relying on chat history.
