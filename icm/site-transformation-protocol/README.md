# MACS Site Transformation Protocol

Status: canonical, reusable ICM workflow
Owner: MAXX / MACS Digital Media
Purpose: transform an existing website without jumping from prompt to visual redesign.

## Core sequence

`TRUTH → POSITION → ARCHITECT → PROVE → DESIGN → BUILD → GAUNTLET → LEARN`

Design is phase 5, not phase 1.

## Operating law

An agent may only enter a phase when the previous phase's required outputs exist or the protocol explicitly marks them as already proven. Every phase has inputs, process, outputs, evidence, and a stop/human-check condition. Brownfield capabilities are preserved unless evidence justifies removal.

## Quality bar rule

A design bar must be named, fetchable, and comparable. For MACS Client Zero the current bar is the live `wearecollins.com` experience for restraint, hierarchy, visual proof, editorial confidence, whitespace, storytelling, and mobile quality. The protocol never authorizes copying another company's protected identity, copy, imagery, or case-study content.

## Agent portability

A memoryless agent starts at `00_router/CONTEXT.md`, loads only the current phase, and must pass `WALK_TEST.md` before it is trusted to execute a transformation.

## Client instances

Client-specific truth and decisions live under `icm/clients/<client>/`. The protocol is canonical; client folders instantiate it rather than copying and drifting it.
