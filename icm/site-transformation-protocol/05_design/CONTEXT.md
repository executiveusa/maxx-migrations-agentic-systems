# 05 — DESIGN

## Purpose
Translate the approved positioning, architecture, and proof into a coherent visual/interaction system.

## Inputs
- approved Phase 02 positioning
- approved Phase 03 wireframes
- Phase 04 proof/assets
- named fetchable quality bar
- brand constraints and accessibility requirements

## Process
Define palette, typography, grid, spacing, image behavior, media ratios, navigation, buttons, materials, transitions, responsive rules, and motion. Prefer restraint and real media over generic SaaS chrome. Motion must support comprehension and respect reduced-motion preferences.

## Outputs
- `VISUAL_SYSTEM.md`
- design tokens
- responsive component rules
- motion/reduced-motion rules
- approved high-fidelity key-page designs

## Evidence
Rendered key states at required viewports, accessibility checks, and side-by-side reference comparisons where useful.

## Human/authority check
Owner approves the visual direction before broad implementation.

## Exit condition
The system is specific enough that two competent builders would produce recognizably the same brand experience, while leaving implementation details flexible.
