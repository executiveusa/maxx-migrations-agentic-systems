# Phase 05 Design Doctrine

Status: canonical lazy-loaded design authority for Site Transformation Protocol

## Source lineage

This doctrine normalizes two owner-supplied design sources into enforceable agent rules:

1. `03-Collins-Level-Website-Design-Protocol-1-1-.pdf` — strategic website workflow, review gates, creative-territory requirement, usability/accessibility/sovereignty scoring, anti-slop rules, and independent review standard.
2. `HEART_AND-SOUL.md` — subtraction doctrine: minimum necessary interface around maximum useful capability; automate invisible complexity; preserve human control at consequential moments.

This file does not authorize copying COLLINS identity, layouts, copy, imagery, typography, or finished visual work. The reference is a rigor/quality bar.

## Design hierarchy

Optimize in this order:

1. user outcome
2. clarity
3. trust
4. ease
5. speed
6. accessibility
7. consistency
8. delight
9. visual polish
10. novelty

Never sacrifice a higher priority to improve a lower one.

## Core rule

**Minimum necessary interface around maximum useful capability.**

Complex backend systems are acceptable. Complex customer interfaces are not.

Prefer:

`system detects → system prepares → human reviews when consequential → system completes`

over
`user configures → user manages → user fixes`.

## Strategy before styling

Do not begin Phase 05 from a fashionable component, palette, animation, template, or generated hero.

The design must be traceable to:
- customer and situation;
- desired business/social outcome;
- approved positioning;
- real content;
- proof;
- constraints/protected assets;
- governing creative idea;
- accessibility and performance requirements.

## Brand behavior before decoration

For each client, define:
- WHAT WE BELIEVE
- HOW WE BEHAVE
- WHAT WE REFUSE
- WHAT PEOPLE SHOULD FEEL
- WHAT PEOPLE SHOULD REMEMBER
- WHAT PEOPLE SHOULD DO

Translate attributes into visual, content, and interaction behavior. Do not stop at adjectives.

## Three divergent creative territories — mandatory

Before selecting a final high-fidelity visual direction, produce at least three materially different territories:

1. restrained
2. expressive
3. experimental

Each must differ in:
- governing idea
- grid
- typography behavior
- image treatment
- pacing
- motion
- navigation expression
- signature moment
- emotional character

All three must remain usable and accessible.

The owner/architect selects one territory. The agent may recommend one but may not silently average all three together.

Each territory records:
- DIRECTION NAME
- GOVERNING IDEA
- STRATEGIC CONNECTION
- CUSTOMER EFFECT
- GRID
- TYPOGRAPHY
- COLOR LOGIC
- IMAGERY / ART DIRECTION
- MOTION
- NAVIGATION
- SIGNATURE MOMENT
- ACCESSIBILITY RISKS
- PERFORMANCE RISKS
- IMITATION RISK
- COMMERCIAL ADVANTAGE

## Cliché blacklist

Reject by default unless the governing idea genuinely requires it:
- generic centered hero
- purple/blue gradient as identity
- glassmorphism
- floating dashboard mockup
- default three-card feature row
- default bento grid
- pill-shaped everything
- generic geometric sans with no brand rationale
- random luxury serif
- unrelated stock lifestyle photography
- decorative 3D spheres
- endless marquee
- arbitrary parallax
- template testimonials
- fake metrics
- AI-brain imagery
- unnecessary rounded rectangles

## Content before containers

Real content determines composition, section order, typography, imagery, pacing and interaction.

Do not force content into generic cards because a component library makes cards convenient.

## Art direction requirements

Define an intentional image world:
- subject
- casting
- environment
- lighting
- composition
- lens behavior
- crop/focal point
- movement
- grade
- texture
- illustration/graphic system
- animation/archival/AI rules where relevant

Every major visual must have a job. Imagery must be owned/licensed/approved. Mobile crops and alt-text requirements must be defined.

Distinctiveness test:
- could this image system belong to a competitor?
- is it recognizable without the logo?
- does it express the governing idea?
- is it rooted in the organization's real story?
- does it contain proprietary/controlled material?
- does it create memory rather than merely polish?

## Subtraction test

For every element ask:
1. Can this be removed?
2. Can this be combined?
3. Can the system infer it?
4. Can it appear only when needed?
5. Can the next action be understood without explanation?
6. Can the workflow require fewer decisions?
7. Can advanced capability live elsewhere?

Continue until another removal would damage usefulness, confidence, accessibility, trust, or human control.

Every button, card, panel, navigation item, sentence, animation, metric, setting, modal and status must earn the attention it consumes.

## Self-evident before experimental

Users must not need to decode:
- what the organization does
- where they are
- what is clickable
- how to navigate
- what to do next
- what happens after an action

The work should become surprising **after** it becomes understandable, not instead of understandable.

## Motion

Every animation must serve hierarchy, orientation, feedback, narrative pacing or brand expression.

Reject:
- content-blocking intros
- scroll hijacking
- motion on every section
- hover-only information
- delayed button response
- reading-slowing text reveals
- purposeless parallax
- navigation-dependent cursor effects
- missing reduced-motion alternatives
- multiple unrelated animation languages

## Phase 05 outputs

A client-specific Design phase is not complete until it has:
- three divergent territory documents/prototypes
- owner-selected territory
- `VISUAL_SYSTEM.md`
- design tokens
- art-direction/source manifest
- responsive rules
- motion/reduced-motion rules
- high-fidelity key-page prototype using real content/assets
- accessibility/performance risk notes
- explicit Phase 05 approval receipt

Only the selected/approved territory may authorize Phase 06 broad implementation.

## Independent review / release quality

Builder cannot self-approve.

Final downstream review should cover six lenses:
- customer/commercial value
- Krug usability
- creative direction/distinctiveness
- accessibility
- technical quality
- sovereignty/ownership/rollback

Release targets inherited from the owner-supplied protocol:
- overall weighted score >= 8.5/10
- usability >= 8.5
- visual design >= 8.5
- originality/art direction >= 8.5
- accessibility >= 8.5
- primary conversion flow >= 9.0
- zero critical failures
- zero broken controls
- zero mobile overflow
- zero unverified claims
- rollback documented
- owner approval recorded

A high average cannot hide a critical failure.
