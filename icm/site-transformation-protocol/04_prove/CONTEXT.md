# 04 — PROVE

## Purpose
Replace explanation with real evidence before visual design.

## Inputs
- Phase 01 proof inventory
- Phase 02 message hierarchy
- Phase 03 wireframes

## Process
For every planned public claim or section, ask whether a real image, artifact, result, client story, founder story, demonstration, screenshot, or source can prove it. Gather permission and provenance. Classify assets as PROVEN, NEEDS VERIFICATION, or DO NOT CLAIM.

## Outputs
- `ASSET_MANIFEST.md`
- case-study source packs
- founder/story media inventory
- product/work artifact inventory
- claim-to-evidence map
- missing-proof list

## Evidence
Original files, source URLs, client approvals, screenshots, receipts, measurements, and source metadata.

## Human/authority check
Owner/client approves sensitive public proof, names, likeness, case-study details, and performance claims.

## Exit condition
Every high-importance homepage/page claim has either evidence, an approved owner statement, or is removed/rewritten. No placeholder proof is allowed to masquerade as real work.
