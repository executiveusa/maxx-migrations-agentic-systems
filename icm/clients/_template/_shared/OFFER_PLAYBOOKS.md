# Four MAXX entry paths — one suite

Exactly four commercial buckets; all use the same backend, client brain, approval ledger, Hermes coordinator and capability adapters. The founder hears the outcome, not the tool list.

| Bucket | First narrow job | Specialist path | Acceptance metric | Gate |
|---|---|---|---|---|
| **Reset** | Find and repair one lead or conversion leak | Audit → research → web/CRM draft → verify | baseline vs. recovered/handled inquiries | approval for production changes and external sends |
| **Momentum** | Turn approved source material into useful posts and follow-ups | Research → copy → PARE/Clipz → owner review → Postiz/Buffer Blaster | approved posts, qualified replies, bookings | brand/publication approval |
| **Scale** | Remove one repetitive founder bottleneck | Operations → Composio/tool adapter → runbook → monitor | hours returned and exception rate | approval for access, spend, writes |
| **Launch** | Test one offer with one credible acquisition path | Position → design → copy → landing/intake → evidence | qualified conversations or paid orders | approval for claims, pricing and publishing |

## Default first proof
Recover or respond to existing inbound leads before broad autonomous content generation. Read the actual client baseline, ask permission to connect one system, draft the response, and prove receipt/booking. One client-specific metric and one owner acceptance are required.

## Specialist capabilities (proposed; not all connected)
- Lead/revenue: source-qualified research, CRM triage, draft follow-up, booking.
- Marketing: editorial plan, social drafts, publishing only after approval, analytics.
- Creative: copy, design with PARE, video/UGC drafts with MAXX Clipz or reviewed adapter.
- Operations: SOP, project follow-through, safe app integration with per-client Composio.
- Finance/tax: reconcile and organize documents for accountant review, never autonomous tax advice, filing or payment.
- Technical: website diagnostics, reversible fixes, tests and deployment only after review.

Each task must identify the owning repo, adapter readiness, allowed scope, expected cost, output artifact, acceptance test and rollback. Do not promise a capability merely because its repository exists.
