# MACS Public-Site Wireframe — v1

Status: approved starting architecture; copy and final visual treatment are not locked.

## Primary navigation

`Programs · Work · Story · Built Here · Notes · See if we're a fit`

## Homepage

### 1 — POINT OF VIEW / HERO
Purpose: establish the company before explaining mechanisms.

Layout:
- minimal header / menu
- one dominant real-media field: Stacy + Stavarai, Northwest setting, client/business environment, or equivalent real work
- one large thesis line
- one quiet primary action: `See if we're a fit`

Do not include architecture diagrams, SaaS feature lists, pricing tables, permissions matrices, or multi-step technical explanations.

### 2 — QUIET CREDIBILITY + PROGRAMS
Purpose: identify the business situations MACS takes responsibility for.

Structure:
- quiet line: Pacific Northwest / father + son / selective 90-day engagements
- one short Programs thesis
- four working entries as editorial rows, not SaaS cards:
  - Reset
  - Momentum
  - Scale
  - Launch
- each gets one situation/outcome sentence and a path deeper

### 3 — WORK
Purpose: prove capability visually.

Structure:
- one dominant real project/case-study media block
- one-line business problem frame
- up to two secondary real projects when verified
- CTA: `See the work`

Initial proof candidates:
- ASC3ND
- MACS / Client Zero
- third client only after verification and permission

### 4 — FATHER + SON / STORY
Purpose: make the human combination the differentiator.

Structure:
- large real Stacy + Stavarai image/video
- compressed story: Stacy's fragmented-vendor/ownership lesson + Stavarai's current UGC/content/commerce perspective
- CTA: `Our story`

Avoid generic equal co-founder cards and age jokes.

### 5 — BUILT HERE
Purpose: show cultural/technical depth without becoming a SaaS catalog.

Thesis: things MACS built because it needed them to do better work.

Candidate modules:
- Agent MAXX
- Buffer Blaster
- Home Team AI Lab
- selected social/research/media experiments

Each module answers `why did we build this?`, not `what are all the features?`.

### 6 — FIT + FOOTER
Purpose: qualify rather than pressure.

Structure:
- large Northwest/business media
- short selectivity statement
- 90-day minimum engagement statement
- CTA: `See if we're a fit`
- footer navigation, contact, social, Notes/newsletter

Existing technical/product pages may remain available during migration but should not dominate primary navigation unless later positioning explicitly requires it.

## Program template

Program label → large situation/outcome line → real flagship media/proof → short situation narrative → what changed → impact/evidence → related work → fit CTA.

## Work template

Case Study label → client + one-line problem frame → full media hero → short situation narrative → real artifacts/media → what changed → evidence/impact → intentional whitespace/pacing → next work.

## Story template

Stacy before MACS → fragmented vendors/rented systems/accountability problem → founding conviction → Stavarai/current-generation operating perspective → how the two roles combine → ownership/trust promise.

## Copy discipline

Each homepage section should be explainable with one thought plus one dominant image. Detail moves deeper. If a section needs five cards or a paragraph wall to explain itself, revisit architecture before adding copy.
