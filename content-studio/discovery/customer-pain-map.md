# Customer Pain Map

| Pain the owner feels | What they usually want instead | Editorial response |
|---|---|---|
| Too many subscriptions | Fewer tools that clearly earn their place | Cost audits, cancel/consolidate frameworks, no-prescription guidance |
| Customer data in multiple places | One understandable source of business truth | Lead maps, ownership maps, company-brain explainers |
| Leads need manual chasing | Reliable follow-up without babysitting software | Trace the lead path, identify one leak, automate only the stable step |
| Automations are scary to touch | Simple workflows with visible boundaries | Explain triggers/actions in plain English and preserve human approval gates |
| AI feels like another confusing app | A system that can handle bounded boring work | Show jobs/outcomes first, tools second; distinguish chat, agents and automation |
| Platform lock-in or migration fear | Ability to move data, context and workflows | Migration inventories, export/readiness guidance, handoff expectations |
| E-commerce feels technical | A store the owner can understand and improve | Shopify basics, product trust, UGC briefs, mobile clarity |
| Business knowledge lives in people's heads | Portable organized context | Company-brain/folder methods and one-home-per-fact guidance |
| Technology consultants push solutions first | A trustworthy diagnosis | Doctor analogy, provider-selection questions, MACS No-Prescription Promise |
| Owner has no time to become technical | Plain-language next steps | Answer first, one bounded action, no terminal-first teaching |

## ADHD editorial test

Before a draft can move to review:

1. Can the reader identify the problem in the first screen?
2. Is the main answer near the top?
3. Is there one clear next action?
4. Are there no more than five major ideas in one visible block?
5. Is technical vocabulary explained only when necessary?
6. Does the article reduce decisions rather than create another tool-shopping list?
